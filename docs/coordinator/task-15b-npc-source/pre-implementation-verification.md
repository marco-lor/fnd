## Decision

**15B remains necessary and is an appropriate independent implementation unit.** The page still opens a complete `echi_npcs` collection listener; the sidebar independently opens a `createdAt DESC` listener. Neither uses the existing shared repository runtime. Replace these with one route-owned hook and one small NPC repository built on the existing runtime. Pass its ordered rows/loading/read-error into the sidebar, and use the same entity objects for the page lookup.

The critical contract is that the two existing queries are **not equivalent**: Firestore `orderBy('createdAt', 'desc')` excludes documents without that field. Sharing the sidebar's ordered query would silently remove those NPCs from map lookup. The smallest compatible solution is a single complete collection subscription with a complete ID lookup and a separately derived sidebar order. Preserve existing sidebar membership by excluding only documents where `createdAt` is absent; `null` is present. Do not add limits, a migration, detail fetches, or a second listener.

This is a reader/ownership change. Marker partitioning, virtualization, shared marker portals, map asset delivery, writer replacement, and private-marker deletion policy remain outside 15B.

## Smallest sound implementation

1. Add a small NPC-specific repository and ordering helper, either in one module or a module plus a focused model file. One `subscribeShared` descriptor wraps one labeled, unbounded `collection(db, 'echi_npcs')` listener. Use a static low-cardinality metric key, for example `echi.npcs.subscribe.v1`; private subscription keys may include auth scope if needed.
2. Use `applyDocChanges` rather than another reconciliation/cache framework. Keep its internal collection `orderedIds/items` in Firestore collection order because its `oldIndex/newIndex` updates depend on that order. Derive the sidebar by sorting a **copy**, never by mutating the structural runtime arrays. Maintain raw entity values plus authoritative Firestore document ID; `items` and `byId[id]` should reference the same NPC object. If `applyDocChanges` returns the existing result, return the previous derived result too; otherwise a new wrapper/sorted array would defeat no-op identity preservation. One modified NPC should normalize one entity and preserve the other 499 objects. Sorting 500 references on a changed snapshot is acceptable for 15B; an incremental balanced index is unjustified.
3. Define and test local sorting compatibility before replacing the old query. Retain createdAt DESC and **document ID DESC** for equal values (Firestore's implicit tie-break direction). Handle actual timestamps at seconds/nanoseconds precision and the checked-in ISO strings using Firestore's type ordering; do not coerce mixed strings/timestamps into a new chronological order or use locale sorting for IDs. Distinguish absent `createdAt` from present null. Pending server timestamps need explicit handling using snapshot information/public `data({ serverTimestamps: 'estimate' })` as appropriate; compare pending/acknowledged insertion against the original ordered query in the emulator instead of assuming null equals missing. Keep all records in `byId`. Do not add a generic schema migration or a general Firestore engine to this task.
4. Add a focused route hook bound to `useAuthSession()` UID + `repositoryAccessGeneration`. Reuse existing runtime cleanup; maintain an effect-local active guard and scope-tagged result. Old-scope rows/lookup must be masked on the render when scope changes, not just after an effect. Null user means no NPC subscription. Equivalent user objects with the same UID/generation must not resubscribe. A new generation for the same UID must reconnect after `setRepositoryActor` closed the previous listener.
5. Replace the page's local NPC effect/state with this hook. Pass ordered `npcs`, loading, and read error to `NpcSidebar`. Remove only its read subscription and read-owned state. Keep local create/edit/delete state and mutation errors: current `npcError` serves both reads and writes, so read-error props must not make mutation errors read-only or allow an Add/Edit click to erase an active read failure. Define terminal error behavior explicitly (empty coherent reader state plus a visible error is a simple option); a new successful subscription clears old read errors. Offline cached snapshots are not terminal listener errors.
6. Leave display fallbacks at render sites. The existing `MapMarkerItem` already derives normalized title/image/description/notes (`EchiDiViaggio.js:102-107`), so sharing raw entities does not require pushing `'-'` or trimmed values into the editor model. Preserve the existing page-level fallback behavior in drag/move labels where those use `npcById`.
7. Update query registry ownership to the new repository call site and one actual full-collection contract. Mark future paging as deferred; do not activate the registry's old “first 100-row” aspiration. The plain collection query needs only automatic indexing; no new composite index or rules deployment is required. Add a specific one-NPC-listener gate and preserve the existing zero-listener-after-cleanup gate.

Avoid keying the page/sidebar/popup by snapshot revision or replacing the current fade/CSS as part of data sharing. For the same NPC ID, an ordinary data update should update the existing popup DOM node rather than replay its entrance or discard focused controls. Local modal drafts must survive unrelated NPC snapshots; authoritative media revision lookup must still use the latest shared entity at save time.
