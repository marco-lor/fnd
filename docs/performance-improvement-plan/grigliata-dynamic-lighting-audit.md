# Grigliata dynamic lighting audit

21 November 2026 · Staging player view and local source revision `bc4d0e971912`

**Fix the loss of current vision at nine sources and the fog-tile write race first.** For visual quality, make lamps obey their own walls in player view. For speed, start with exploration rasterization and per-source geometry reuse. Video playback behaved well on the staging map.

An independent browser run passed 128 combinations of portal type, open state, sight and light blocking flags, fog mode, selected lamp, and viewer position. A separate Firestore emulator run used two player clients and a manager with the checked-in rules. A fresh client read back all three discovered bits after concurrent player writes. A manager hide followed by a stale player discovery retained only the two expected bits. A delayed write from a prior grid alignment preserved the newer tile. Hiding the last migrated tile retained an empty marker for the next session. A 900-tile brush operation committed in groups of 200, 200, 200, 200, and 100, and the next hide succeeded.

## Backend and regression coverage

Door toggles already update the small wall-state document independently. Authoring edits have different costs. For example, changing scene darkness serially writes the authoring document, the player render projection and the background summary. An import also resets wall state. A partial failure can leave different revisions in use. Stage slider edits locally, publish a coherent revision with a batch, and use a version check or transaction where two managers can edit concurrently. Keep player fog writes scoped to the owner. There is no server-side ray caster to scale in this flow. **Repair the performance fixture before judging a change.** Its 200 walls lack effective blocking flags, its player projection contains empty light and darkness arrays, and its 1,024 stored masks are all zero. Assert nonzero effective blockers, gradients, active sight polygons and nonempty atlas groups before timing. Keep both the small real map and the dense synthetic map. Record source recomputations, layer draws, tile decodes, dirty groups, write concurrency and acknowledged final masks. Test player, manager and View as player with identical geometry. ## Evidence scope

The staging observations came from the signed-in player board in T3 Chromium on Windows. They cover navigation, zoom, reset, the ruler, video playback, a phone-sized CSS viewport and ordinary Firestore delivery. Movement, door edits, source-count changes and competing writes used a disposable local scene with this checkout's actual masks, geometry, Firestore hooks and rules. The write tests controlled the interleaving of the application's read/merge/write and transaction protocols. Local timings exclude remote service latency. Physical-phone GPU performance, other browsers, long soaks, reconnect timing and multi-manager edit frequency remain unmeasured.

To reproduce the two-source timing, use the checked-in map, two 12-square viewers centered at (1230, 1050) and (1230, 930), and the default 256 fog rays plus wall-endpoint directions. The alternate centers were (1230, 1110) and (1350, 1050). For the 20-light stress case, lay out 20 × 10 wall segments on 200 px centers with each segment extending 150 px right and 100 px down. Place two rows of ten lights at x = 300 + 310 × column, y = 700 + 350 × row. Use the default 96 lighting rays plus endpoints. For the closed-door pixel check, put a vertical door at x = 200, the viewer at (140, 120), the lamp at (230, 120), and sample (180, 120). Moving the viewer across the closed door switched which side the fog covered.

**480 existing tests passed across 16 suites.** The board suite emitted a React maximum-update-depth warning during test cleanup. Claude Fable 5.2 at xhigh independently reviewed the paths and challenged the priorities. That review distinguished the existing fog-mode tint design from a regression, and prompted the additional manager-hide/player-reveal experiment.
